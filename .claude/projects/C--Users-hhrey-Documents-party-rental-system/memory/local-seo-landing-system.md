Building a scalable, multi-brand local-SEO landing system for city pages (e.g. `/jumper-rentals/perris`). Goal: rank for "jumper rentals {city}", "bounce house rentals {city}", "water slide rentals {city}", "party rentals {city}" for both Lias Party Rentals (liaspartyrentals.com) and CRB Jumpers (crbjumpers.com).

**Key architecture decisions:**
- New SEO routes live under `src/app/(site)/` so they auto-inherit brand chrome/theme + per-brand `metadataBase` from `(site)/layout.tsx`. No changes to `proxy.ts` / brand config needed — brand resolves from host (`x-brand-slug`) → `getBrandSlug()`, `?brand=` is dev fallback.
- **Self-canonical per brand domain** (not cross-canonical) — they are genuinely different businesses. Per-city uniqueness (real neighborhoods/landmarks/ZIPs/FAQs) + per-service angle + per-brand voice avoids duplicate-content penalties.
- Data layer is **brand-neutral**; brand voice/NAP injected at render. Reuse `getProducts`/`getRentalCategories` (already brand-aware) — no new queries. Server-rendered only.

**Routes planned:** `/party-rentals/[city]`, `/jumper-rentals/[city]`, `/water-slide-rentals/[city]`, `/bounce-house-rentals/[city]` (4 thin route files sharing one template + loader, each passing a `service` key).
